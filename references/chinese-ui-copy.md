# 中文界面文案

## 通用规则

- **用词**。先查看目标界面同类文案、项目词表和设计规范。同一对象、操作和状态用同一个词。保留业务人员熟悉且有明确含义的术语，如「驳回」和「退回修改」各自对应不同流程时分别使用。
- **语气**。把用户要做的事或看到的结果放在前面。能省略主语时直接写动作或状态。需要称呼时按产品约定使用「你」或「您」。用具体要求引导修正，如「结束日期须晚于开始日期」。
- **标点和数字**。中文句子通常用全角标点。短按钮、标题、标签和单句字段提示通常省略句号，多句说明用标点断句。保留品牌、缩写和文件格式的写法。按项目规范处理空格、数字、单位和日期，例如「最多上传 5 个 PDF 文件」。
- **可读性**。在实际组件、窄屏和动态值最长的情况下看文案是否易扫读、是否完整。优先保留操作对象、结果、限制和下一步。为图标操作写清可访问名称，例如「删除设备」或按项目模式提供含设备名称的标签。
- **本地化**。繁体界面沿用目标地区用词，如跟随既有界面使用「儲存」或「儲存變更」。项目有不同地区版本时分别检查译文。保留 `{count}`、`{name}` 这样的变量，按真实取值检查句子和显示宽度。

## 简体中文 B 端

项目已有文案规范时优先使用。以下规则以 Ant Design 为参考，适用于管理台、审批、运维和数据处理等企业场景。需要核对具体用词、语气、标点或组件场景时，按任务查阅文末对应的官方 Markdown。

| 场景 | 写法 | 示例 |
| --- | --- | --- |
| 按钮和链接 | 单看标签也能判断动作。上下文已经明确对象时可用短动词。 | `保存`、`导出报表`、`查看失败记录` |
| 表单和校验 | 字段名说明填什么。格式、单位和大小限制提前说明，报错贴近字段并指出怎么改。 | 字段「设备编号」，错误「请输入 8 位数字」 |
| 进度和反馈 | 区分已受理、处理中和已完成。部分成功时给出可确认的数量及处理失败项的入口。 | 「已导入 {successCount} 条，{failureCount} 条失败。」操作「查看失败记录」 |
| 失败和恢复 | 先说哪一步失败，补充已确认的原因和可用的下一步。原因未知时，只写已知结果及可用操作。 | 「报表导出失败。请重试。」 |
| 空状态 | 区分首次无数据、筛选无结果、加载失败和权限受限。用标题交代状态，提供当前用户能执行的操作。 | 「暂无设备」配「添加设备」，「没有符合条件的设备」配「清除筛选」 |
| 权限和审批 | 说明受限对象或当前流程状态。按实际权限和流程提供下一步。 | 「待部门负责人审批」，「无权导出报表」配「申请导出权限」 |
| 危险操作 | 标题点明动作和对象，正文说明影响和能否恢复，主按钮写明将执行的动作。 | 标题「删除这 3 台设备？」正文「删除后，设备记录无法恢复。」按钮「取消」「删除设备」 |

审校时用同一业务对象串读页面标题、表格操作、对话框和结果提示。用户通过按钮或链接进入新页面时，核对操作标签与目标页标题是否使用同一名称。对照需求、产品实现或已有交互说明核实数值上限、数据影响、权限入口和恢复方式。产品行为还未确认时，先用能确认的事实写文案，并在交付说明中列出待确认项。
